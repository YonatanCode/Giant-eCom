# Store Page — Overview (read this first)

Shared context for every section agent. Each `NN-*.md` spec assumes you've read this file.

## What we're building

The store detail page at `/store/:id` (`src/app/store/[id]/page.tsx`), from the Figma design
**"Store locator - Invested"** — file `W7HSN3Dg73m7QLr6Gplzgl`, root node `554:3278`.
One long landing page for the mock store "Giant Bennebroek", assembled from ~14 sections.

## Tech & conventions

- **React 19 + Next.js App Router + TypeScript + Tailwind v4.** No component library, **minimal dependencies** (org policy — do not `pnpm add` anything without asking).
- Design tokens live in `src/app/globals.css` under `@theme` (generated by `scripts/gen-css.py` — **never hand-edit token values**). Style with **semantic token utility classes only**, never raw hex.
- Icons: **inline SVG** components in `src/components/store/icons/` — no icon package.
- Each section is a component in `src/components/store/`, takes a typed slice of `Store` as props, and is rendered by `src/app/store/[id]/page.tsx`.

## Token cheat-sheet (classes that exist)

**Typography** (fluid, responsive): `text-display-xl|l|m|s`, `text-heading-l|m|s`, `text-body-l|m|s`,
`text-action-l|m|s` (use for UPPERCASE eyebrows), `text-nav-l|m|s`, `text-price-l|m|s`, `text-product-title-l|m|s`.
Headings use `--font-heading` automatically (h1–h4); eyebrows are uppercase `text-action-s`.

**Colors** (light/dark + Giant/Liv aware — use semantic, not foundation):
`bg-base-surface`, `bg-base-surface-subtle`, `text-base-text`, `text-base-text-heading`, `text-base-text-muted`,
`text-base-text-emphasis`, `border-base-border`, `border-base-border-divider`,
`bg-action-surface`, `text-action-text`, `text-action-text-link`, `text-action-text-on-dark`, `border-action-border`,
commerce: `text-commerce-text-discount`, `bg-commerce-surface-new`, `text-commerce-text-new`, `bg-commerce-surface-dcf`.

**Spacing** (use for `p-* m-* gap-*`): `none xxxs(2) xxs(4) xs(8) s(12) sm(16) m(24) ml(32) l(48) xl(64) xxl(96) xxxl(112) xxxxl(144)`.
Page horizontal padding: `px-(--layout-page-padding)` (16/32/48 at mobile/tablet/desktop).

**Dark sections:** add `className="dark"` (or `dark bg-base-surface`) on the section root. The `.dark`
variant remaps base/action colors automatically — keep using the same semantic classes inside.

## Layout & full-bleed

`src/components/LayoutShell.tsx` wraps all routes. For the store page its `<main>` must NOT add horizontal
padding or vertical padding (the foundation pass removes it), so sections can render **full-bleed** colored
bands. Each section provides its own background and inner max-width container via the shared `Section` wrapper.

## Shared components (build in the foundation pass, before section agents)

All under `src/components/store/`:

| Component | Purpose | Key props |
|-----------|---------|-----------|
| `Section.tsx` | Full-bleed band + centered inner container | `bg?: 'surface' \| 'subtle' \| 'dark'`, `id?`, `className?`, `children`. Inner: `container mx-auto w-full !max-w-page px-(--layout-page-padding) py-xl` |
| `SectionHeader.tsx` | Eyebrow + title (+ optional right description) | `eyebrow`, `title`, `description?`, `align?` |
| `Button.tsx` | Buttons & button-links | `variant: 'primary' \| 'secondary'`, `size?: 32\|40\|48`, `href?`, `children` |
| `FeatureChip.tsx` | Icon + label pill | `icon`, `label` |
| `CtaLink.tsx` | Text + arrow-right link | `label`, `href` |
| `StoreSidePanel.tsx` | Store type, title, contact rows, features, actions | `store: Store` (used by Hero + Directions map) |
| `icons/*` | Inline SVG, 16px & 24px | each takes `className`/`size` |

Local cards (build inside their section): `StatCard`, `CollectionCard`, `EmployeeCard`, `TimelineStep`, `ArticleCard`.
FAQ accordion: use native `<details>/<summary>` (no JS state).

## Data

All content comes from `src/data/store.ts` — import `getStore(id)` (returns the `Store` mock) and the `Store` type.
Each section receives only its slice (e.g. `store.service`). **Do not invent fields** — if you need a field that
isn't in the `Store` type, add it to `store.ts` and the mock, and note it in your section's checklist.

Images are placeholder paths under `/images/store/*` (not committed). Use them as `src`; layout/aspect-ratio
matters more than the actual asset. Real assets (or Figma-downloaded ones) can replace them later.

## Per-section workflow (for the agent building a section)

1. Read this file + your `NN-section.md`.
2. Pull the live design for your node:
   `mcp__claude_ai_Figma__get_design_context` and/or `get_screenshot` with `fileKey=W7HSN3Dg73m7QLr6Gplzgl` and the node id in your spec.
3. Build one component in `src/components/store/`, props-driven from the `Store` slice.
4. Use only token classes above. Match spacing/typography to the design; desktop-first, stack gracefully ≤768px.
5. Verify: `pnpm dev`, view `/store/1`; compare to the node screenshot. No horizontal overflow on mobile. `pnpm build` type-checks.

## Build order

1. **Foundation pass** (one agent): `Section`, `SectionHeader`, `Button`, `FeatureChip`, `CtaLink`, icon set,
   and the `LayoutShell.tsx` `<main>` un-padding. Wire `src/app/store/[id]/page.tsx` to `getStore(id)` and render placeholders.
2. **Section agents**, top→bottom: 00 Navigation → 01 Hero → 02 Intro → 03 Service → 04 Banner → 05 Story →
   06 Team → 07 Inventory → 08 DCF → 09 Directions → 10 FAQ → 11 Articles → 12 Brands → 13 Footer.
   `StoreSidePanel` (shared) should land with Hero (01) since Directions (09) reuses it.
